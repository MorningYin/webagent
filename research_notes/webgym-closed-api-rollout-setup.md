- **Correct resume recipe (CRITICAL — the framework's skip is by `(task_id, trajectory_index)`, and trajectory_index is NOT task-stable across a re-sampled run, so naive resume re-runs everything):** to resume without redoing, BUILD THE TASK LIST TO EXCLUDE already-done task_ids, and let `resume_checkpoint_path` MERGE the done ones at save time. Steps: (1) extract done task_ids from the checkpoint (`traj[0]['observation'].task.task_id`); (2) write `run_v3_tasklist.jsonl` = (target_total − done) NEW tasks from the pool, excluding done ids; (3) set `train_tasks`=that file, `train_tasks_rollout_size`=its length, `resume_checkpoint_path`=the checkpoint, `save_path`=same run dir; (4) launch → "Loaded N", "Found <done> completed", "Skipping 0" (correct — list has no overlap), final file = done + N. Do NOT include the done tasks in the list (their trajectory_index won't match → they'd be re-run, creating duplicates). Current: 4901 new + merge 99 = 5000.

**Mass-failure recovery (e.g. sealed-proxy death — step-0-blanked thousands of tasks):** symptom = a flood of `Step 0: Screenshot blank after N attempts` (the FIRST screenshot before any LLM call → it's browser/network, NOT the proxy/omnibox; verify network via `curl -x http://127.0.0.1:7891 https://archive.org`). Recovery recipe: (1) load the run's final `.pt`, split GOOD (`len(traj)>=2`) vs garbage (`<2` steps); (2) save GOOD as a fresh `clean_good.checkpoint`; (3) collect garbage task_ids → look up their full records in tasks_filtered.jsonl → `rerun_list.jsonl`; (4) config: `resume_checkpoint_path=clean_good.checkpoint`, `train_tasks=rerun_list.jsonl`, `rollout_size=len(rerun)`, `save_path`=same run; (5) relaunch → re-runs only the failed, merges the good. The monitor now also probes network reachability + step-0-blank spikes so a future outage alerts immediately instead of silently wasting thousands of tasks.

**Cold-start blank burst (DON'T over-react / over-restart):** every fresh rollout launch produces a one-time burst of ~60-70 `Step 0: Screenshot blank` (≈15-22 failed tasks) in the first ~30-60s, because all `server_size` browsers do their initial navigation at once and herd the sealed proxy (limited static-IP bandwidth). It SETTLES on its own (blank count goes flat, fin climbs, runs clean) — verified by watching `grep -c 'Screenshot blank' run log` go flat over ~2 min. This is NOT worker-count (36 runs 400+ fine in steady state), NOT stale browsers (fresh fleet bursts too), NOT network. Each restart re-triggers the burst, so repeated restarting is what makes "lots of failures at startup" recur — the fix is to STOP restarting and let it settle. The ~15-22 cold-start casualties are a small re-runnable loss. (Future option to eliminate the burst: bump screenshot `max_retries` in rollout.yaml from 2 → ~4-5 so herd-blanked step-0 tasks retry and recover once the herd clears — apply only at a natural restart, not as a reason to restart.)

So a per-step SFT sample = (messages[text+image refs] → response text); it's standard VLM SFT, train=inference consistent (raw_prompt == what was sent). `scripts/export_trajectories.py` emits ready `steps_sft.jsonl` ({prompt, response} per step) — must ship the images/ dir alongside; paths are absolute (rewrite if moving machines). **Process-kill reliability gotcha (caused a real incident):** /proc-based "stop rollout" sweeps repeatedly exited 144 / partially failed, leaving an OLD rollout main alive (it kept serving the :6006 dashboard with its stale rollout_size while a newer launch was blocked from binding 6006) — symptom: dashboard total ≠ the rollout_size you configured. ALWAYS verify ZERO rollout python processes before relaunching: `python -c "...count cmdline contains 'rollout.py' and '/python'..."` should print 0; if a main is daemonized (ppid 1) it survives parent-kill, and killing the main orphans hundreds/thousands of workers that must also be SIGKILL-swept (saw 1589 orphans once). Confirm `ss -ltn | grep 6006` is empty (old dashboard gone) before launching the new run, then confirm the new dashboard `total` ≈ your rollout_size.
